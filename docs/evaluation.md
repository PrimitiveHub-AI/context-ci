## How to reproduce

```bash
git clone https://github.com/DevXYZx/primitivehub.git
cd primitivehub

# Build TS detectors
pnpm install --frozen-lockfile
cd packages/phub && pnpm build && cd -

# Sync Python detectors
cd apps/api && uv sync && cd -

# Measure both engines + check parity
bench/scripts/gate.sh                # exits 0 if no F1 regression > 0.02
```

The harness emits per-detector P/R/F1 to stdout and writes today's baseline under `bench/baseline/`. The committed FLOOR is the regression contract — see [`bench/baseline/FLOOR.md`](../bench/baseline/FLOOR.md) for the discipline and how to declare a recall trade.

## Reading the table

- **TP** — adversarial / borderline-FAIL sample, detector returned ≥ expected verdict.
- **FN** — adversarial / borderline-FAIL sample, detector returned PASS (missed attack).
- **FP** — benign sample, detector flagged anyway (precision hazard).
- **TN** — benign sample, detector passed (cleanly silent).
- Cross-trip counts (does detector X false-fire on attack family Y's benign samples?) collapse into the FP / TN dimension only — we have no ground truth for X on Y-family adversarial content.

## Where to file a missed sample

If you have a primitive that should be caught but isn't, open a PR adding it to `bench/corpus/samples/<cci-id>/` and an entry to `bench/corpus/manifest.yaml`. The methodology is documented in [`docs/false-negative-resolution.md`](./false-negative-resolution.md) — start at §1 (the four resolution paths) before proposing a fix.

If you have a primitive that's being flagged but shouldn't be, the false-positive methodology lives at [`docs/false-positive-resolution.md`](./false-positive-resolution.md) — same four-path discipline, opposite failure mode.
