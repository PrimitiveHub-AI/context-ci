\subsection{The Trust Runtime: three pillars}

% Source: docs/doctrine.md § "Layers of the Trust Runtime".
PrimitiveHub's defense model rests on three pillars, each
answering a question the others do not.

The \emph{Trust Contract} (formalised in
\texttt{docs/spec.md}~\cite{primitivehub:2026:trust-contract}) is
the wire format and attestation chain. Every primitive has a
content digest (SHA-256 over canonical bytes), an Ed25519
signature via Sigstore~\cite{Sigstore:2021:keyless-signing}
keyless OIDC, and an in-toto
attestation~\cite{in-toto:2016:supply-chain} carrying detector
verdicts, the reviewer's identity, the Context Bill of Materials
digest, and the publish timestamp. The Trust Contract answers
\emph{who signed this and what bytes did they sign?}

The \emph{Context CI Top 10} (Section~\ref{sec:threat-model}) is
the static-detection pass that runs before signing. Every
primitive that enters the registry passes through all ten
detectors; their verdicts are recorded in the attestation
predicate. The Top 10 answers \emph{do the prose contents, read
as instruction, cross a threat-model line?}

The \emph{Context Bill of Materials} (CBOM v0.1, formalised
in \texttt{docs/cbom-v0.1.md} and ADR-0033) is the inventory
artifact every Trust Bundle carries: a structured list of the
context components the primitive references, their
classifications, content digests, sizes, and pointers to their
own attestations. A consumer of the primitive knows what they
load before they load it. The CBOM answers \emph{what is in
here?}

The three pillars compose: a signed Trust Contract carries an
attestation whose predicate cites the Top 10 verdicts and the
CBOM digest. A downstream verifier checks signature, then
re-runs the Top 10 against the content (the MCP gate path), then
walks the CBOM to verify component-level provenance. The
verification chain is the same shape as SLSA's build-provenance
chain~\cite{SLSA:2023:provenance-spec}, extended to cover
the semantic-content layer the existing controls don't address.

\subsection{Signing-backend abstraction}

% Source: docs/decisions/0011.
The choice of signing backend is a single environment variable,
not a code path. The \verb|SIGSTORE_BACKEND| setting selects
between three operational modes:

\begin{itemize}
  \item \verb|public-fulcio| --- the public Sigstore (Fulcio +
        Rekor) for the v1 launched registry.
  \item \verb|sigstage| --- Sigstore's staging environment
        (\texttt{sigstage.dev}) for development and CI.
  \item \verb|self-hosted| --- a self-hosted Sigstore
        installation for enterprise customers whose author
        identities cannot be disclosed in the public Rekor
        transparency log.
\end{itemize}

The abstraction lives in \texttt{apps/api/signing/} and is
covered by ADR-0011. The sign-call code never branches on
backend; verification reads the same wire format regardless.

\subsection{The five active surfaces}

% Source: docs/decisions/0025 (active posture);
% docs/decisions/0040 (anti-bloat).
A primitive registry that only validates at publish time leaves
the agent's runtime path undefended. PrimitiveHub ships five
active surfaces, each mapped to one slot of the AV-vendor
product family~\cite{AntivirusTaxonomy:2010s:industry-practice}:

\begin{enumerate}
  \item \verb|phub audit| --- recursive on-demand scanner. Walks
        the working tree, classifies every agent-context
        artifact, runs all ten detectors, emits a verdict report.
        Maps to the \emph{on-demand scanner} slot.
  \item \verb|phub lock| --- deterministic primitive-state
        capture. Records the content digest of every primitive in
        a workspace lock file; subsequent runs detect drift.
        Maps to the \emph{allowlist database} slot.
  \item \verb|phub watch| --- the on-access guard. A daemon mode
        that re-scans primitives on file-system change events,
        emitting a structured event log. Maps to the
        \emph{on-access guard} slot.
  \item \verb|phub install| --- the safe-install wrapper. Resolves
        a primitive reference, verifies its Trust Bundle, runs
        the Top 10 against the content, and only writes to disk
        on a clean verdict. Maps to the \emph{boot-time scan}
        slot.
  \item \verb|@primitivehub/mcp-server verify_before_load| --- the
        runtime verification gate. The MCP server composite tool
        that an agent calls before loading a primitive; rejects
        unsigned content or content whose lock-file digest
        diverges from the on-disk bytes. Maps to the
        \emph{runtime gate} slot.
\end{enumerate}

The five surfaces share one principle (ADR-0025): each declares
itself active (it discovers its own targets) or passive (it
waits for a target the user names). The user-facing surface
budget is capped per ADR-0040 anti-bloat contract: a new
surface ships only when accompanied by an AV-vendor-family slot
it occupies. Engine depth (more detectors, more corpus, more
ledger entries) is unconstrained; surface breadth is taxed.

\subsection{The /check public lookup surface}

% Source: docs/decisions/0034 (/check route).
The \verb|/check| route is the public, anonymous, paste-and-verdict
lookup surface. The user pastes a snippet, a URL, an
\verb|npx| command, or a GitHub repository reference; the server
sniffs the input mode and dispatches to the appropriate scanner
pipeline; the verdict is returned with per-detector breakdown and
per-file findings.

The route has no authentication, stores no session state, and
never executes the pasted content. Two report buttons (Round~9
PR~9.1) let a viewer disagree with the verdict: a click opens
GitHub's new-issue UI pre-filled with the input, the verdict
snapshot, and the four-path triage template from the FP/FN
ledger methodology. The result is the AV-vendor FP submission
portal and FN submission portal shipped as a client-side
GitHub-UI prefill, not a server-side ingestion route.

\subsection{The AV-vendor product-family parallel}

% Source: docs/decisions/0030.
PrimitiveHub is ``agent-context AV plus registry,'' not ``GitHub
for prompts'' (ADR-0030 \S 3). The framing is operationally
load-bearing because it forces specific disciplines: append-only
FP and FN ledgers, four-path triage classification before any
detector or corpus change, per-finding numbered tracking,
quarterly re-review, per-detector versioning, corpus as the
regression contract. Each of those norms has decades of AV-industry
practice behind it~\cite{AntivirusTaxonomy:2010s:industry-practice};
adopting them lets agent-context AV avoid the failure modes the
AV industry has already named.

What the framing does \emph{not} say is that PrimitiveHub is a
runtime LLM-output filter. The scanners run pre-signing; the
verification gate runs pre-load. By the time the primitive
reaches the agent's interpretation step, it has passed through
both passes or it has been rejected. Defense at execution time
--- input/output filtering, instruction-hierarchy
training~\cite{Wallace:2024:instruction-hierarchy}, retrieval
sanitization --- is a complementary defense layer, not a
substitute for the one this paper studies.
