\section{System Design}
\label{sec:system-design}

\subsection{The Trust Runtime: three pillars}

PrimitiveHub's defense rests on three pillars, each answering a question
the others do not.

The \emph{Trust Contract}~\cite{primitivehub:2026:trust-contract} is the
wire format and attestation chain. Every primitive carries a
\contentdigest{} (SHA-256 over canonical bytes), an \edsig{} produced
through Sigstore keyless OIDC~\cite{Sigstore:2021:keyless-signing}, and
an in-toto attestation~\cite{in-toto:2016:supply-chain} recording the
detector verdicts, the reviewer identity, the Context Bill of Materials
digest, and the publish timestamp. The Trust Contract answers \emph{who
signed this, and what bytes did they sign?}

The \emph{Context CI Top~10} (Section~\ref{sec:threat-model}) is the
static pass that runs before signing. Every primitive entering the
registry passes through all ten detectors, and their verdicts are
written into the attestation. The Top~10 answers \emph{do the contents,
read as instruction, cross a threat-model line?}

The \emph{Context Bill of Materials} (CBOM) is the inventory each Trust
Bundle carries: the context components a primitive references, their
classifications, digests, sizes, and pointers to their own attestations.
A consumer knows what they load before they load it. The CBOM answers
\emph{what is in here?}

The pillars compose. A signed Trust Contract carries an attestation that
cites the Top~10 verdicts and the CBOM digest. At the registry boundary,
the verifier checks the signature, re-runs the Top~10 against the
content, then walks the CBOM to verify component provenance. The shape
mirrors SLSA's build-provenance chain~\cite{SLSA:2023:provenance-spec},
extended to the semantic-content layer the existing controls leave
uncovered.

We are precise about \emph{where} each check runs, because security
properties live at enforcement points. The Top~10 runs in full at two
places: at registry publish, before signing, and inside the
\texttt{phub} on-demand audit over a working tree. The agent-side
\texttt{verify\_before\_load} gate currently enforces signature and
lock-file digest integrity plus the working-tree audit it wraps;
re-running the Top~10 \emph{inside the MCP server at the moment of load}
is partially implemented and tracked as planned work
(Section~\ref{sec:conclusion}). A reader should therefore not assume the
load-time gate re-derives every detector verdict; it verifies that the
bytes match a previously attested, scanned digest.

\subsection{One environment variable for the signing backend}

The signing backend is configuration, not a code path. A single setting
selects the public Sigstore (Fulcio + Rekor) for the launched registry,
Sigstore's staging environment for development and CI, or a self-hosted
Sigstore for enterprises whose author identities cannot appear in the
public transparency log. The sign-call code never branches on backend,
and verification reads the same wire format regardless.

\subsection{Active surfaces, not just a publish-time linter}

A registry that validates only at publish time leaves the agent's
runtime path undefended. PrimitiveHub ships five surfaces, each mapped
to a slot in the antivirus product family:

\begin{itemize}
  \item \texttt{phub audit}: a recursive on-demand scanner that walks
        the working tree, classifies every agent-context artifact, and
        runs all ten detectors.
  \item \texttt{phub lock}: deterministic state capture; it records each
        primitive's \contentdigest{} so later runs detect drift.
  \item \texttt{phub watch}: an on-access guard that re-scans primitives
        on file-system change events.
  \item \texttt{phub install}: a safe-install wrapper that verifies a
        Trust Bundle, runs the Top~10, and writes to disk only on a
        clean verdict.
  \item The MCP \texttt{verify\_before\_load} gate: a runtime check an
        agent calls before loading a primitive. It rejects unsigned
        content and content whose on-disk bytes diverge from the
        attested lock-file digest. Load-time Top~10 re-scanning inside
        the gate is partially implemented (the detectors are exposed
        separately as the \texttt{scan\_text} tool).
\end{itemize}

Each surface declares itself active (it discovers its own targets) or
passive (it waits for a named target). The surface budget is capped: a
new surface ships only when it occupies an AV-family slot nothing else
holds. Engine depth (more detectors, more corpus, more ledger entries)
is unconstrained; surface breadth is taxed, because a passive tool
cannot defend the file the user did not know to scan.

\subsection{A public, anonymous lookup}

The \texttt{/check} route is a paste-and-verdict surface. A user pastes
a snippet, a URL, an \texttt{npx} command, or a repository reference;
the server detects the input mode, dispatches to the right scanner, and
returns a per-detector, per-file verdict. The route has no
authentication, stores no session state, and never executes the pasted
content. Two report buttons let a viewer dispute a verdict by opening a
prefilled issue carrying the input, the verdict snapshot, and the
four-path triage template. The result is an AV-style false-positive and
false-negative submission portal, implemented as a client-side prefill
rather than a server-side ingestion route.

\subsection{Scanner-as-product discipline}

Framing PrimitiveHub as agent-context antivirus plus a registry is
operationally load-bearing: it imports specific disciplines, namely
paired append-only ledgers, four-path triage before any detector change,
numbered per-finding tracking, per-detector versioning, and the corpus
as the regression contract. Each has decades of AV practice behind
it~\cite{Christodorescu:2003:static-malware}. What the framing
does not claim is a runtime output filter: the scanners run pre-signing,
the gate runs pre-load, and by the time a primitive reaches the agent it
has passed both passes or been rejected. Execution-time defenses such as
instruction-hierarchy training~\cite{Wallace:2024:instruction-hierarchy}
remain complementary, not a substitute for the layer studied here.
