\begin{abstract}
Modern AI agents do not only execute code; they also obey context.
Skills, system-prompt fragments, Model Context Protocol (MCP) server
descriptions, and repository-level \texttt{AGENTS.md} files all shape an
agent's behavior
at load time, before the user issues a request. Existing supply-chain
controls can verify who signed such an artifact and whether its bytes
changed, but not the harder question: whether the signed prose is safe
for an agent to follow. A context primitive can pass every provenance
check and still tell the agent to fetch remote instructions, run a shell
command, leak credentials, or trust a fabricated authority claim.

We present Context CI, a static-validation pipeline for this
agent-context supply chain, implemented in the PrimitiveHub registry. It
is organized around the Context CI Top~10, a ten-category operational
taxonomy in which each attack class is tied to implemented detectors,
labeled corpus samples, and reproducible measurements. To test
portability and implementation drift, we implement every detector twice,
in Python and
TypeScript, and measure both engines against the same 124-sample corpus
under a CI regression gate and a per-sample replay tool.

On the 99-sample in-sample slice the two engines agree byte-for-byte and
reach a macro F\textsubscript{1} of 0.991. The 25-sample held-out slice
exposes a more important diagnostic result: the Python engine catches
all 25 attacks while the TypeScript engine catches 18, with the misses
concentrated in the unsafe-shell-install, credential-exfiltration,
prompt-injection, and poisoned-naming categories. We report that gap
rather than tune it away; it is what a held-out diagnostic is built to
surface, and the in-sample gate alone would hide it. The corpus,
taxonomy, detectors, gate, and replay workflow are open source and
reproducible from a clean clone, providing an initial benchmark
foundation for semantic validation of the agent-context supply chain.
\end{abstract}
