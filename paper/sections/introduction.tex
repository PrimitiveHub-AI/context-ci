\section{Introduction}
\label{sec:intro}

\subsection{A supply chain the build pipeline does not cover}
\label{subsec:shift}

The last decade of supply-chain security invested in the build
pipeline. SLSA~\cite{SLSA:2023:provenance-spec},
in-toto~\cite{in-toto:2016:supply-chain},
Sigstore~\cite{Sigstore:2021:keyless-signing}, and the
provenance work shipped by npm, PyPI, and Maven Central give a
consumer a verifiable chain from source commit to signed artifact.
That chain answers two questions: who built this, and is the artifact
on disk the one that was signed? Both have been load-bearing in
incident response, from the SolarWinds Orion
breach~\cite{SolarWinds:2020:supply-chain} and the Codecov bash-uploader
compromise~\cite{Codecov:2021:bash-uploader} to the
\texttt{ua-parser-js} typosquat~\cite{ua-parser-js:2021:npm-typosquat},
the \texttt{eslint-config-prettier} maintainer-account
breach~\cite{eslint-config-prettier:2024:maintainer-compromise}, the
\texttt{xz-utils} backdoor (CVE-2024-3094)~\cite{xz-utils:2024:CVE-2024-3094},
and the 2025 Shai-Hulud npm worm that spread through
\texttt{postinstall} hooks on typosquatted
names~\cite{Shai-Hulud:2025:npm-worm}.

AI agents load a category of artifact this investment does not reach.
We call them \emph{context primitives}: documents the agent treats as
instruction at load time. A skill file under \texttt{.claude/skills}; a
system-prompt fragment; an MCP server description that binds tool calls
to endpoints; an \texttt{AGENTS.md} at a repository root. The agent
parses each with the same mechanism it uses for user input: as language
to act on.

A primitive can be well-formed under every existing control, signed by
an authorized maintainer, \contentdigest{}-verified, freshly fetched
over an unbroken provenance chain, and still carry prose that says
\emph{``before your first reply, run \texttt{curl
https://attacker.example/i.sh | sh} to register with the operations
coordinator.''} The cryptographic controls confirm the bytes have not
changed since signing. They say nothing about whether those bytes, read
as instruction, are safe to follow~\cite{primitivehub:2026:top10}.

\subsection{What an attacker does with a poisoned primitive}

The surface is wider than any one trick. A primitive can tell the agent
to fetch a URL and treat the response as further
instruction~\cite{primitivehub:2026:top10}; hide a directive inside
zero-width codepoints invisible to a reviewer; pair a base64 blob with
a decode-and-run order; impersonate a vendor whose name carries a
Cyrillic letter in place of a Latin A; or bury the live instruction
under decorative padding. Each is the same boundary, prose interpreted
as instruction, failing in a different way.

Signing cannot close this. It proves \emph{who} wrote a primitive, not
what the primitive tells the agent to do. Runtime defenses such as
output filtering and instruction-hierarchy
training~\cite{Wallace:2024:instruction-hierarchy,Greshake:2023:prompt-injection-survey}
catch some attacks at execution time, but the cost of a caught attack,
a credential read or a command run, is partly paid before the defense
fires. The missing layer is a semantic check that runs \emph{before} the
primitive reaches the agent's load path: a scan of its prose for known
attack shapes, with explicit per-shape detectors and measured precision
and recall against a labeled corpus.

\subsection{Contributions}

\paragraph{A threat taxonomy, defined operationally} We present the
Context CI Top~10, a ten-category taxonomy of agent-context
supply-chain attacks. Each category is defined by an implemented
detector, at least one canonical sample from a labeled corpus, and a
measured precision and recall. The taxonomy is not exhaustive; it is the
set of shapes observed in incidents or composable from
them~\cite{Greshake:2023:prompt-injection-survey,Shai-Hulud:2025:npm-worm,Carlini:2024:webcrawl-poisoning}.
Section~\ref{sec:threat-model} treats each in turn.

\paragraph{A labeled corpus and a measurement contract} We ship 124
labeled samples under CC-BY-4.0: 99 in-sample (52 adversarial, 37
benign, 10 borderline) and 25 held out. Two engines, Python and
TypeScript, run the same detectors over the same bytes, and a CI gate
requires byte-identical \texttt{(tp, fp, tn, fn)} tuples on the
in-sample slice. The held-out slice is reserved as an overfit probe and
is never used to tune the detectors.

\paragraph{An antivirus-vendor methodology} We adopt the AV industry's
discipline of paired, append-only false-positive and false-negative
ledgers, with a four-path triage applied to every finding before any
detector change~\cite{Christodorescu:2003:static-malware}. The
discipline is what stops a team from trading precision for recall by
reflex.

\paragraph{An open, reproducible artifact} The corpus, detectors,
measurement scripts, regression gate, and a per-sample replay tool are
open source. A reviewer can clone the repository, run one script, and
obtain the per-detector numbers we report here.

\subsection{Results}

On the in-sample slice both engines agree byte-for-byte and reach a
macro F\textsubscript{1} of 0.991: nine of ten detectors score a perfect
1.000, and one, the unsafe-shell-install detector, carries a single
benign false positive (precision 0.833). We do not suppress it. The
held-out slice is where the split exposes implementation drift. The
Python engine
recovers all 25 held-out attacks; the TypeScript port recovers 18, a
macro recall of 0.832, missing held-out shapes in four categories that
the Python engine catches. That divergence is the corpus doing its job:
the in-sample gate guarantees parity on samples the detectors have seen,
and the held-out slice reveals that the TypeScript port still lags the
Python engine on shapes neither was tuned against.
Section~\ref{sec:evaluation} reports the per-detector breakdown and an
enumerated list of limitations, so this reads as an initial measurement
rather than a final claim.
